# DanmuAI Live2D 桌面显示验证计划

> 工单 ID：`W-LIVE2D-SCREEN-POC-PLAN-001`  
> 阶段：第一阶段，隔离式屏幕显示 POC  
> 状态：计划文档已就绪，待其他 IDE 在 Windows 实机执行 POC  
> 本文只授权独立实验，不授权接入 DanmuAI 正式运行链路。

## 1. 目标

在 Windows 桌面上验证一个 Live2D `.model3.json` 模型是否能够被原生透明窗口稳定承载，并回答以下问题：

- 模型及纹理、物理、动作、表情等依赖能否从本地目录完整加载；
- 窗口能否无边框、背景透明、始终置顶且默认不抢夺输入焦点；
- 窗口能否拖动、缩放、调整透明度，并能切换鼠标穿透；
- 在普通窗口和无边框游戏窗口前是否仍能保持预期置顶行为；
- 连续运行 30 分钟是否无明显闪烁、白底、黑底、崩溃或异常资源占用；
- 是否至少能由代码触发一次模型动作和一次表情；
- 删除整个 `experiments/live2d-screen-poc/` 后，DanmuAI 是否仍能正常启动。

## 2. 明确非目标

第一阶段不得实现或讨论为“已接入”的功能：

- 不修改 `app/pet/`、`app/overlay.py`、`app/danmu_engine/`、`main.py`、`app/` 其他业务代码；
- 不替换现有序列帧桌宠，不修改弹幕 Overlay、AI 调度、正式配置、设置页、路由或打包流程；
- 不做摄像头面捕、OpenSeeFace、MediaPipe、头部捕捉或真人表情捕捉；
- 不把模型名、动作名、表情名、机器绝对路径写死为 DanmuAI 业务契约；
- 不把测试模型、纹理、SDK 私有文件、密钥或商业资源提交到 GitHub；
- 不在 POC 未通过前启动正式集成或设置页开发；
- 不把浏览器窗口、浏览器标签页或现有 Web 控制台作为显示载体。

## 3. 允许修改区域

本工单执行阶段仅允许修改：

POC 所需的本地依赖、SDK、模型和运行时缓存放在实验目录之外或被 Git 忽略的位置。若执行者认为必须修改 `.gitignore`，应先停止并向负责人申请单独授权；不得用忽略规则掩盖误放入仓库的模型文件。

## 5. 实验边界与资源策略


建议由执行 IDE 建立如下结构，但不得为了凑齐结构添加无用途文件：

```text
├─ docs/                # 执行记录或平台说明
```

- `E:\test\PB` 仅是本机测试资源位置，不得复制到仓库、正式程序目录或打包产物。

- 模型、纹理、动作、表情、SDK 二进制和授权文件不提交、不打包、不复制到正式程序目录。
- 执行者必须在报告中记录实际渲染后端、SDK/绑定版本、运行时版本、依赖安装方式和许可证风险；不能因为“能运行”而默认可以随 DanmuAI 分发。
- 若依赖下载、许可证、GPU/驱动或 Windows 原生能力无法确认，应记录为阻塞，不得绕过授权改用不符合目标的浏览器方案。

## 6. 分阶段执行

### 阶段 A：环境与模型可用性确认

1. 记录 Windows 版本、Python/运行时版本、显卡/驱动、显示器数量和 DPI 缩放。
2. 确认实际 `.model3.json`、纹理和依赖文件完整，先做离线路径校验。
3. 确认渲染 SDK/绑定的许可证和本地安装方式；没有可合法使用的原生渲染路径时停止并报告。

### 阶段 B：最小原生窗口 POC

只实现一个可独立启动和关闭的窗口：

- 无边框、透明背景、角色可见；
- 不打开浏览器，不依赖 DanmuAI 进程；
- 启动时不主动抢焦点，关闭时释放资源；
- 模型路径由参数或配置传入；加载失败显示可诊断错误并安全退出。

### 阶段 C：交互与窗口行为

按验收清单逐项实现并验证：拖动、缩放、透明度、鼠标穿透开关、置顶、普通窗口前置、无边框游戏前置、动作触发、表情触发。所有窗口操作必须保持主线程/GUI 线程安全，不得用忙循环制造高占用。

### 阶段 D：稳定性与隔离验证

完成短时回归后执行 30 分钟连续运行，记录 CPU、内存、GPU（若可取得）、窗口状态和日志。最后关闭 POC、暂时移走或重命名实验目录，验证 `python main.py` 的启动路径未被改变。

### 阶段 E：报告与门禁裁决

执行者填写 `02_POC验收清单与测试报告模板.md`，逐条给出“通过 / 失败 / 未覆盖”，附日志、截图或录屏路径。没有完整报告视为未通过，即使窗口曾经成功显示。

## 7. 通过门禁

只有以下项目全部通过，才允许提出正式集成工单：

1. Windows 桌面原生显示，无需浏览器；
2. 背景透明、无明显白底/黑底/闪烁；
3. 窗口可拖动、缩放、调透明度；
4. 鼠标穿透可开关，且开关后行为可恢复；
5. 默认置顶且不抢焦点；普通窗口和无边框游戏模式均完成验证；
6. `.model3.json` 及其依赖成功加载；
7. 代码至少成功触发一次动作和一次表情；
8. 连续运行 30 分钟无崩溃，资源占用无异常增长；
9. 删除实验目录不影响 `python main.py` 启动；
10. 完整测试报告已生成，并明确记录许可证、模型授权和未覆盖风险。

任一项失败、未覆盖或仅靠推测，结论均为“POC 未通过”，不得进入正式集成。
