# 交给其他 IDE 的执行提示词

你正在执行 DanmuAI 的 `W-LIVE2D-SCREEN-POC-PLAN-001`。你的任务是完成**隔离式 Live2D 桌面显示 POC**，不是把 Live2D 接入 DanmuAI。

1. 仓库根 `AGENTS.md`；
2. `.local-ai/workorders/当前仓库状态.md`；
3. 本目录 `01_隔离式屏幕显示POC计划.md`；

5. `.local-ai/prompts/ai-project-context.md` 中的线程和 UI 事实。

## 允许区与绝对禁止

只允许修改：

```text
experiments/live2d-screen-poc/
```

绝对禁止修改或接入：

```text
app/
main.py
web/
requirements.txt
package.json
锁文件、CI、构建、发布配置
```

不要提交 `.model3.json`、纹理、动作、表情、BOOTH 模型、SDK 私有文件、DLL、密钥或其他大二进制。不要修改 `.gitignore`，除非先得到负责人明确授权。不要打开浏览器作为角色显示窗口。

## 执行任务

请按以下顺序执行，并在每一步记录真实命令、退出码和证据：

1. 记录执行前 `git status --short`，区分既有并发改动和本工单改动。
2. 检查当前 Windows、Python/运行时、GPU/驱动、DPI、多显示器和模型资源。当前模型资源根目录是 `E:\test\PB`，请在该目录中定位实际的 `.model3.json` 及其依赖。
3. 确认可合法使用的原生 Live2D 渲染 SDK/绑定、版本、许可证和依赖安装方式。若无法确认，停止实现并报告阻塞，不要退回浏览器方案。
4. 在实验目录内实现一个可独立启动/关闭的最小原生透明无边框窗口。默认验证输入可指向 `E:\test\PB`，但模型路径必须仍由启动参数或本地示例配置提供，不能把该路径、模型名或动作名写死进业务代码。
5. 实现并验证置顶但不主动抢焦点、拖动、缩放、透明度调整和鼠标穿透开关。
6. 用代码触发至少一个动作和一个表情，并记录实际使用的资源标识。不要把这些名称变成 DanmuAI 全局业务契约。
7. 执行普通窗口和无边框游戏模式测试，记录成功、失败或未覆盖，不要把“理论上支持”填写为通过。
8. 运行 30 分钟稳定性测试，记录开始/结束 CPU、内存、可取得的 GPU 指标、日志和异常。
9. 关闭 POC 后移走或重命名实验目录，验证 `python main.py` 的源码启动路径未被 POC 改变。不得为了验证而修改正式代码。
10. 用 `02_POC验收清单与测试报告模板.md` 生成完整报告；所有条目必须填写“通过 / 失败 / 未覆盖”，附截图、录屏、日志和性能记录路径。

## 实现约束

- GUI 对象只在其 GUI 主线程创建和操作；禁止忙循环轮询导致高占用。
- 加载失败必须有可诊断错误并安全退出，不能静默显示空窗口。
- 默认不抢焦点；鼠标穿透打开后必须仍有可恢复控制方式。
- 透明区域必须是真透明，不接受白底、黑底或伪透明背景。
- 关闭窗口后不得留下实验进程、临时服务或隐藏窗口。
- 不要添加摄像头、OpenSeeFace、MediaPipe、面捕或真人捕捉组件。
- 不要改 DanmuAI 正式配置、桌宠、Overlay、AI 调度、设置页或打包流程。

## 停止条件

遇到以下任一情况立即停止相关实现并在报告中标为“阻塞”：

- 需要修改允许区之外的文件；
- 无法确认 SDK 或模型的许可；
- 只能通过浏览器窗口实现目标；
- 透明窗口、置顶/游戏兼容性或模型依赖无法可靠验证；
- 需要把模型或私有 SDK 放入 Git 才能运行。

## 交付内容

最终只交付实验目录内的必要代码和文档，以及一份完整测试报告。最终消息必须明确：

- 修改了哪些文件；
- 没有修改哪些关键区域；
- 每个验收项的结果和证据位置；
- 运行的命令与退出码；
- SDK/模型许可证和未确认风险；
- 是否满足进入正式集成工单的门禁。

即使 POC 成功，也不要修改 `app/pet/` 或开始正式集成；只输出“可申请下一张工单”的结论。
