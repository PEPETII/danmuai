# 重构【弹幕知识库 → 知识包】界面

## 1. 任务背景

当前【弹幕知识库 → 知识包】功能已经具备以下能力：

- 知识包管理
- 文本、TXT、Markdown、网页导入
- 自动整理资料
- 生成知识条目
- 任务进度查看
- 检索预览

但当前界面更偏向开发者视角，存在以下问题：

1. 页面信息密度过高。
2. 功能和配置连续堆叠，缺少清晰的信息层级。
3. 新用户不知道知识包是什么。
4. 新用户不知道正确的操作顺序。
5. 字段缺少行内辅助说明。
6. 高级功能与基础功能处于相同视觉层级。
7. 知识包状态无法直接反映下一步应进行的操作。
8. 新建知识包仍使用浏览器原生 `window.prompt()`，与项目整体界面不一致。

本任务需要重新设计【知识包】界面的信息架构、交互路径和辅助文案，使第一次使用该功能的普通用户也能快速理解。

---

## 2. 任务目标

将知识包页面改造成一个明确、渐进、对新用户友好的知识管理流程。

用户进入页面后，应能直接理解以下内容：

- 知识包是什么。
- 知识包会如何影响弹幕生成。
- 应该先进行哪一步。
- 导入资料后系统会做什么。
- 知识条目是什么。
- 什么时候应该启用知识包。
- 哪些设置属于高级功能。

本任务以调整前端页面为主，不修改现有知识库后端接口、数据库结构、导入流程和检索算法。

---

建议在页面顶部使用步骤条、流程卡片或简洁的引导模块展示。

目前所有模块连续堆叠，用户难以判断使用顺序。

# 6. 页面顶部改造



## 6.1 页面标题

保留标题：

```text

```

要求：

- 步骤顺序必须清晰。
- 文案应简短。

- 新建知识包
- 刷新
- 检索预览

调整为：

- `刷新`：降级为次级按钮或图标按钮。
- `检索预览`：移动到“高级工具”区域，不再与新建按钮同级展示。

# 8. 新建知识包流程



## 8.1 移除原生输入框

移除通过以下方式创建知识包的交互：

```javascript
window.prompt()
```

改为项目统一样式的弹窗或内联表单。

## 8.2 新建表单字段



### 名称

必填字段。

行内说明：

```text
用于区分不同资料集合，例如“原神角色资料”。
```

建议占位符：

```text
例如：黑神话悟空角色与剧情
```



### 描述

选填字段。

行内说明：

```text
简单说明这个知识包包含什么内容。
```

建议占位符：

```text
例如：包含主要角色、剧情背景、Boss 和常用梗
```



## 8.3 表单交互要求

- 名称为空时，显示明确的行内校验提示。
- 不使用浏览器原生警告框作为唯一反馈。
- 创建成功后自动进入知识包详情页。
- 关闭弹窗时不创建知识包。
- 保持现有创建知识包 API 不变。
- 弹窗需要支持键盘操作和焦点管理。

系统会读取网页正文并自动整理。

# 14. 导入时 AI 整理弹窗



## 14.1 设计目标

用户提交资料后，系统需要立即提供明确反馈，避免用户误以为页面卡住、导入按钮无效或任务已经失败。

弹窗需要表达：

- 资料已经成功提交。
- AI 当前正在执行哪个处理步骤。
- 当前处理进度。
- 用户是否可以关闭弹窗并让任务继续运行。
- 处理成功、部分失败、完全失败或取消后的结果。



## 14.2 触发时机

当用户点击以下任一操作，并且后端成功创建导入任务后，立即展示弹窗：

- 整理这段文本。
- 导入 TXT。
- 导入 Markdown。
- 读取网页。

不得在任务尚未创建成功时展示虚假的处理状态。

如果提交前校验失败，应在原表单中展示行内错误，不打开整理弹窗。

## 14.3 交互拓扑

```text
用户提交资料
    ↓
前端校验输入
    ↓
后端创建导入任务
    ├─ 创建失败 → 表单内展示错误
    └─ 创建成功
         ↓
展示“AI 正在整理资料”弹窗
         ↓
复用现有任务轮询机制同步状态
         ├─ 处理完成 → 展示成功结果
         ├─ 部分失败 → 展示警告和失败详情
         ├─ 处理失败 → 展示原因和重试入口
         ├─ 用户取消 → 调用取消接口
         └─ 后台继续 → 关闭弹窗但任务继续
```



## 14.4 弹窗基础结构

建议结构：

```text
AI 正在整理资料

正在将导入内容转换为可检索的知识条目。
处理时间取决于资料长度，请不要关闭应用。

当前步骤：正在拆分内容

已处理：18 / 32

[██████████░░░░░░]

已用时间：00:24

[后台继续处理] [取消整理]
```

要求：

- 使用项目现有模态框样式。
- 不使用浏览器原生 `alert()`、`confirm()` 或 `prompt()`。
- 不允许只展示旋转图标而没有文字说明。
- 弹窗必须展示当前阶段。
- 有明确总量时展示进度条。
- 无明确总量时展示非确定性进度动画。
- 不得伪造百分比或固定时长。
- 弹窗打开时锁定背景滚动。
- 弹窗关闭后恢复到触发按钮或合理区域的焦点。



## 14.5 标题与资料名称

弹窗标题默认使用：

```text
AI 正在整理资料
```

如果当前任务具有显示名称或文件名，可以展示：

```text
AI 正在整理：西游记角色设定.md
```

长名称必须截断或换行，不得造成横向溢出。

## 14.6 阶段文案

弹窗根据任务阶段动态更新。


| 内部阶段       | 用户显示      |
| ---------- | --------- |
| queued     | 正在准备资料    |
| extracting | 正在读取资料    |
| chunking   | 正在拆分内容    |
| organizing | AI 正在整理知识 |
| finished   | 资料整理完成    |
| failed     | 资料整理失败    |
| cancelled  | 已取消整理     |


推荐辅助文案：

### 正在准备资料

```text
正在检查资料格式并创建处理任务。
```



### 正在读取资料

```text
正在提取网页、文本或文档中的有效内容。
```



### 正在拆分内容

```text
正在把较长资料拆分为适合检索的内容片段。
```



### AI 正在整理知识

```text
正在识别事实、梗、反应方式和表达参考。
```



### 资料整理完成

```text
资料已经转换为可参与弹幕生成的知识条目。
```



## 14.7 进度展示

弹窗应复用任务接口已有数据：

- `processed_chunks`
- `total_chunks`
- `generated_items`
- `failed_chunks`
- `status`
- `stage`

有总片段数时，进度计算为：

```text
processed_chunks / total_chunks
```

展示示例：

```text
已处理 18 / 32
56%
```

如果 `total_chunks` 不存在或为 `0`：

- 使用非确定性进度条。
- 只展示当前阶段。
- 不显示虚假的百分比。
- 不显示未经计算的预计剩余时间。



## 14.8 已用时间

可以展示本次弹窗打开后的已用时间：

```text
已用时间：00:24
```

要求：

- 该时间仅表示已经处理多久。
- 不得将其描述为后端精确执行时间。
- 不提供不可靠的预计完成时间。



## 14.9 完成状态

任务状态变为 `completed` 后，不要立即静默关闭弹窗。

展示：

```text
资料整理完成

已生成 126 个知识条目。
这些内容已经出现在下方“知识条目”区域。

[查看知识条目] [继续添加资料]
```

操作：

### 查看知识条目

- 关闭弹窗。
- 刷新知识条目列表。
- 更新知识包来源数量和条目数量。
- 滚动或聚焦到知识条目区域。



### 继续添加资料

- 关闭弹窗。
- 刷新知识包统计。
- 聚焦到“添加资料”区域。
- 清理已经成功提交的表单内容。

如果生成条目数为 `0`，显示：

```text
资料已经处理，但没有生成可用知识条目。

请检查资料是否包含明确的信息、规则、人物设定或语境内容。
```



## 14.10 部分失败状态

当任务状态为 `completed_with_errors` 时，展示：

```text
资料整理完成，但部分内容处理失败

已生成 108 个知识条目
失败片段：3

[查看知识条目] [查看失败详情]
```

要求：

- 不将部分失败显示为完全成功。
- 不阻止用户使用已经成功生成的知识条目。
- 错误详情优先展示用户可理解的说明。
- 原始错误码放在折叠式“技术详情”中。



## 14.11 完全失败状态

任务状态为 `failed` 或 `interrupted` 时，不自动关闭弹窗。

示例：

```text
资料整理失败

文件编码无法识别。
你可以将文件保存为 UTF-8，或者直接粘贴文本后重新尝试。

[重新尝试] [关闭]
```

要求：

- 展示可理解的失败原因。
- 尽量给出可执行的处理建议。
- 保留“查看技术详情”入口。
- 不丢失仍可恢复的用户输入。
- “重新尝试”需要回到对应导入表单，不能直接重复提交未知数据。



## 14.12 后台继续处理

用户点击“后台继续处理”后：

- 关闭弹窗。
- 导入任务继续运行。
- 不调用取消接口。
- 不停止现有任务轮询。
- 在知识包详情顶部或“处理进度”区域展示轻量状态：

```text
资料正在后台整理
```

同时提供：

```text
查看进度
```

点击后重新打开对应任务的整理弹窗。

## 14.13 取消整理

用户点击“取消整理”后：

1. 展示项目统一的二次确认。
2. 用户确认后调用现有取消任务接口。
3. 弹窗状态更新为：

```text
正在取消整理……
```

1. 后端确认取消后显示：

```text
已取消整理
```

确认文案：

```text
确定取消本次资料整理吗？
```

辅助说明：

```text
已经完成的处理结果是否保留，以当前任务处理规则为准。
```

不得仅关闭弹窗而不取消任务。

## 14.14 刷新与恢复

如果用户在任务运行期间刷新页面、关闭弹窗或重新进入知识包详情页：

- 查询当前知识包的运行中任务。
- 页面展示：

```text
有资料正在整理
[查看进度]
```

- 点击“查看进度”后重新打开对应任务弹窗。
- 不重复创建导入任务。
- 不因弹窗状态丢失而停止轮询。
- 已完成的任务不得重新显示为运行中。



## 14.15 多任务处理

如果同一知识包允许同时存在多个运行中任务：

- 弹窗默认只聚焦本次刚创建的任务。
- 其他任务继续在“处理进度”区域展示。
- 不混合计算多个任务的进度。
- 用户可以从任务列表分别打开进度弹窗。

如果系统实际只允许一个任务同时运行：

- 有任务运行时禁用新的导入按钮。
- 展示：

```text
当前已有资料正在整理，请等待完成后再添加。
```

必须依据现有后端行为实现，不得擅自改变并发规则。

## 14.16 通知策略

当前任务轮询已经可能在完成时展示 Toast。

新增弹窗后需要统一通知策略：

- 弹窗处于打开状态时，以弹窗完成状态为主，不重复弹出相同完成 Toast。
- 弹窗已经关闭并在后台运行时，可以使用 Toast 通知处理完成。
- 同一任务只通知一次。
- 切换知识包后，不得展示上一个知识包的过期完成通知。



## 14.17 无障碍要求

弹窗必须具备：

```html
role="dialog"
aria-modal="true"
aria-labelledby="..."
aria-describedby="..."
```

同时满足：

- 打开后将焦点移动到弹窗标题或主要内容。
- `Tab` 焦点限制在弹窗内部。
- `Esc` 默认等同于“后台继续处理”，不得等同于取消任务。
- 取消任务必须通过明确按钮完成。
- 状态变化区域使用 `aria-live="polite"`。
- 错误状态使用合理的 `role="alert"`。
- 不只通过颜色表达成功、失败或运行状态。



## 14.18 实现约束

- 复用现有任务轮询机制，不创建功能重复的第二套轮询器。
- 弹窗绑定当前任务的 `public_id`。
- 切换知识包、关闭详情页或切换任务时，丢弃过期异步响应。
- 关闭弹窗不等于停止任务。
- 取消任务必须调用现有取消接口。
- 任务完成后刷新：
  - 知识条目列表。
  - 知识包来源数量。
  - 知识条目数量。
  - 知识包当前状态。
- 不修改现有任务状态定义。
- 不修改现有后端任务处理流程。
- 新增文案同步补充中英文 i18n。
- 不在前端模拟后端尚未返回的进度数据。
