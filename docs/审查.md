你的任务是对当前项目执行一次“真实 Bug / 退化风险 / 发布风险”专项审计，输出可直接进入修复排期的报告。

一、审计目标（必须遵守）
聚焦最可能影响以下关键体验的问题：

启动稳定性（双击 EXE、托盘、主窗口、单实例、退出残留）
弹幕主链路（采集 → 生成 → 去重 → 轨道 → Overlay 渲染）
模型调用稳定性与成本控制
配置保存、迁移兼容、SQLite 本地数据可靠性
打包发布、自动更新链路（PyInstaller / Velopack / R2 / Releases）
安全与隐私（密钥、权限、日志泄露、社区后端边界）
目标是“发现并证明问题”，不是做大改造。

二、执行边界（强约束）
先阅读项目结构与关键文档/脚本，再得结论。
必读：README、CONTRIBUTING、docs、scripts、tests、DanmuAI.spec、发布/更新相关脚本。
所有结论必须给出证据：文件路径 + 函数/代码片段 + 可复现路径或触发条件。
禁止“无证据猜测式结论”（如“可能有问题”但不举证）。
默认只做审计，不做重构。
仅当同时满足以下条件才允许修改代码：
Bug 证据充分；
修复范围小且局部；
不改变现有产品设计；
可补充/更新测试；
能明确说明修复前后行为差异。
无法确认真伪时归类为“高风险待人工确认”，不得冒充“已确认 Bug”。
强制关注平台与编码细节：Windows / PowerShell / 中文路径 / UTF-8 / PyInstaller / Velopack / PyQt6 / pywebview / Supabase / Vercel / Cloudflare R2。
读取中文 Markdown、配置、日志、脚本时按 UTF-8 处理，避免 PowerShell 默认编码误判。
PowerShell 优先相对路径；若 rg 对盘符路径不稳定，使用相对路径 + Get-Content -Encoding UTF8 + Select-String。
三、必查模块（逐项打勾，不可跳过）
A. 启动与生命周期
EXE 启动慢、托盘先起但主窗迟迟不出现；
pywebview / PyQt6 Overlay / 托盘 / Web 控制台间阻塞、死锁、重复初始化、异常吞掉；
单实例、关闭重启、后台残留、托盘退出可靠性。
B. 弹幕显示链路
截图、生成、去重、轨道、Overlay 渲染、滚动方向、置顶；
典型故障：直播中不显示、游戏内不置顶、竖屏只首行、轨道追尾、闪烁；
短弹幕/重复/空弹幕/JSON 解析失败/模型异常返回的兜底逻辑。
C. 模型调用与成本
每轮是否重复发送过多上下文/截图；
压缩、超时、重试、异常、空返回、API key 缺失、模型配置错误时是否卡死；
普通/读弹幕/麦克风/自定义模型入口的配置校验一致性。
D. 麦克风 / 语音 / 读弹幕模式

“相关弹幕数量”“额外插入数量”是否真实生效；
读弹幕模式是否误复用主模型配置或忽略自定义配置。
E. 桌宠模式
显示/隐藏/拖动/双击输入/右键菜单/气泡弹幕/多实例状态；
petdex / sprite sheet 切分、idle 动画、缩放、缓存、透明、层级；
桌宠弹幕模式下数量限制与模式切换正确性。
F. 配置、SQLite、本地数据
配置读写、默认值迁移、旧版本兼容、空值/非法值/缺字段；
SQLite 连接、事务、并发、迁移失败兜底；
自定义弹幕库 20000 条场景下卡顿（全量复制/渲染/排序/重复加载）；
.venv-build、构建缓存、临时文件、用户数据误入仓库/产物。
G. 公式化弹幕库 / 外部数据
烂梗公式化、自定义公式化、本地库、导入、标签筛选、随机/自选/AI识别是否真实生效；
外部接口失败/限流/空数据/标签变更/慢网对主链路影响；
采集节流、展示节流、本地缓存是否导致成本上升或 UI 阻塞。
H. 自动更新与发布
DanmuAI.spec、Velopack、R2 链接、Releases 镜像、releases.win.json、版本比较；
安装/卸载/升级是否保留用户数据；
版本显示、更新检查、网络失败、弹窗与跳转可靠性；
MSI 主、Setup.exe 辅是否与文档/下载入口/发布脚本一致。
I. Web 社区与后端 （不做审查）
Vercel/Supabase：密钥泄露、RLS 绕过、限流失效、举报滥用、软删/封禁越权；
前端环境变量、服务端密钥、管理台权限边界。
J. 测试与验收
运行或评估：pytest、scripts/run_acceptance_gates.py、发布检查脚本、overlay/pet/update/config/danmu/mic/tts 相关测试；
若无法运行，必须写清：失败命令、失败文件、断言/报错、缺失依赖、阻塞原因、建议修复；
禁止只写“测试失败”。
