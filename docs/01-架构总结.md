## 1.1 一句话总结

**DanmuAI 是一个高度集成的单体 Qt 桌面应用**，主链路经 8-mixin 组合的 `DanmuApp` 类（约 **3952** 行：main.py 763 + mixins 3189，2026-07-05 复核）聚合所有职责，边界收口层 `app/application/` 已建立但部分失效（5 个文件直读 DanmuApp 私有字段），测试覆盖充分（700+ 用例 / 39066 行）但执行成本高（强制分批避免内存耗尽），整体处于「功能完备但耦合度高、可维护性待提升」的阶段。

## 1.4 线程模型说明

DanmuAI 采用 Qt 主线程 + 多类工作线程的混合模型：

| 线程类型 | 职责 | 关键组件 | 通信机制 |
|----------|------|----------|----------|
| **Qt 主线程** | 截图、回复出队、Qt 对象操作、所有 QTimer | `DanmuApp._on_screenshot_timer`、`GenerationPipeline.consume_reply_queue`（经 `_consume_reply_queue` façade） | 直接到主线程 |
| **QThreadPool（视觉）** | AI HTTP 请求 | `AiRunnable`（`MAX_IN_FLIGHT=1`） | `QMetaObject.invokeMethod` 或 `QTimer.singleShot(0, ...)` 回主线程 |
| **QThreadPool（截图）** | 屏幕截图 | `CaptureRunnable` | 同上 |
| **uvicorn 线程** | FastAPI Web 服务（`127.0.0.1:18765`） | `app/web_console.py` | `WebConsoleBridge` 信号或 `singleShot(0)` |
| **pywebview 子进程** | 桌面壳（WebView2） | `app/webview_shell.py` | 独立进程，IPC |
| **PortAudio 线程** | 麦克风采集 | `sounddevice.InputStream` 回调 | `MicRingBuffer` 互传，主线程 `_poll_mic_utterance()` 消费 |
| **threading.Thread（TTS）** | TTS 播放 worker | `app/danmu_tts_playback._play_worker` | `QMetaObject.invokeMethod` + `QueuedConnection` 投递 `playback_finished` |
| **threading.Thread（bililive）** | bililive_dm 旁路推送 | `app/application/bililive_dm_push_service.py` | httpx + asyncio |

**关键约束**：
- HTTP 线程写 Qt 对象**必须**经 `WebConsoleBridge` 信号或 `QTimer.singleShot(0, ...)` 到主线程
- `MAX_IN_FLIGHT=1`：视觉 AI 请求串行化（避免冷启动连打）
- `MAX_MIC_IN_FLIGHT=1`：麦克风请求串行化
- 截图 tick 间隔由 `_normal_recognition_interval_ms()` 决定（常见默认 5s，非硬编码 1s）

## 1.5 关键设计约束

### 1.5.1 主链路不变量

主链路 `screenshot_timer → _on_normal_capture_tick → _schedule_capture → CaptureRunnable → _on_capture_completed → _trigger_api_call → AiRunnable → _on_ai_reply → _consume_reply_queue` **不得随意改序或旁路**（AGENTS.md §9.2）。新增定时器/线程须同步 `docs/main-pipeline-sequence.md`。

### 1.5.2 场景代际（scene_generation）

- `_visual_reply_stale_reason()`（`app/main_request_context_mixin.py:74`）会丢弃 `scene_generation < current._scene_generation` 的回复，reason = `scene_generation_lagged`
- 新工单**不得**擅自关闭该检查（AGENTS.md §9.3）
- 复合键 `{request_round}:{screenshot_id}:{scene_generation}`（由 `app/main_helpers.py:reply_request_id` 组装）

### 1.5.3 视觉请求看门狗

| 常量 | 值 | 定义位置 | 作用 |
|------|----|----|------|
| `VISUAL_INFLIGHT_WARN_SEC` | 45.0 | `app/main_helpers.py:18` | 视觉在途告警阈值 |
| `VISUAL_INFLIGHT_RECOVER_SEC` | 48.0 | `app/main_helpers.py:19` | 视觉在途强制释放阈值 |
| `REQUEST_WALL_CLOCK_SEC` | 45.0 | `app/main_helpers.py:20` | 请求墙钟超时 |
| `MAX_IN_FLIGHT` | 1 | `app/main_helpers.py:24` | 视觉 AI 并发上限 |
| `MAX_MIC_IN_FLIGHT` | 1 | `app/main_helpers.py:25` | 麦克风 AI 并发上限 |
| `CAPTURE_FAIL_WARN_THRESHOLD` | 3 | `app/main_helpers.py:26` | 截图连续失败告警阈值 |

`reason=inflight_watchdog_recover` 由 `_try_recover_stale_visual_inflight()` 触发；仅告警，不自动复位应用层 `ai_in_flight`。

### 1.5.4 ConfigStore 锁约束

- `_write_lock` 是**非可重入** `threading.Lock`（非 `RLock`）
- 27 处引用，任何**递归回调**内再次获取会自死锁
- `_pool_write_lock` 独立锁，**不可**与 `_write_lock` 嵌套使用

### 1.5.5 Overlay 窗口标志

`app/overlay.py:124-130` 当前使用：
```
FramelessWindowHint | WindowStaysOnTopHint | Tool | BypassWindowManagerHint
```
Win32 扩展样式由 `app/win32_overlay_zorder.py:apply_overlay_exstyles` 应用 `WS_EX_LAYERED | WS_EX_TRANSPARENT`。修改前须读 `app/overlay.py:124-130` 确认。

### 1.5.6 启动参数拒绝

以下参数由 `app/main_launch.py:check_deprecated_launch_args()` 统一拒绝并 `sys.exit(2)`：
- `--qt-ui` / `--legacy-ui`
- `DANMU_QT_UI=1` / `DANMU_WEB_CONSOLE=0`

默认 `python main.py` → Web 控制台 + pywebview + Overlay。

## 1.7 总体评价

**优势**：
1. **测试覆盖充分**：192 个测试文件 / 700+ 用例，覆盖主链路、Web API、配置、模型、麦克风、桌宠、TTS、烂梗等所有子系统
2. **边界收口已建立**：`app/application/` 子包明确分层意图，web_api 层严格遵守 façade 模式
3. **关键路径文档化**：AGENTS.md 详细记录线程模型、reason 字符串、环境变量、模块速查
4. **依赖管理规范**：全部 pin 在 major 内，无 `*` 通配符
5. **CI 完整**：ruff + pytest + Velopack 打包，Windows 全链路验证

**待改进**：
1. **God Object**：DanmuApp ≈3952 行 / 100+ 方法，mixin 通过 `self.*` 共享状态非真解耦
2. **超大文件**：10 个文件超 500 行（最大 `app/config_store/storage.py` 1196 行；`danmu_engine/` 已拆子包）
3. **边界收口失效**：application/ 5 文件直读 DanmuApp 私有字段
4. **层级倒置**：application → web_api 反向依赖
5. **错误处理无层次**：仅 2 个自定义异常无共享基类
6. **类型注解不均**：ai_client.py 仅 24% 覆盖
7. **路由鉴权重复**：68 处内联 `check_token`，无装饰器
8. **测试执行成本高**：700+ 用例需分批执行避免内存耗尽

详细优化建议见 [03-Top5优先优化项.md](03-Top5优先优化项.md)。
